# Handoff: pin uncached packages to the previous nixpkgs on `syncbuild update`

Status: **implemented, NOT tested.** The implementing environment (sandbox) had
no `nix`, no `git-crypt`, and no SSH access to leopard. Only `bash -n` syntax
checks and the dry-run output parser (awk) were verified.

## Goal

When updating the home server **leopard** via `sd leopard syncbuild update`
(all flake inputs updated with `nix flake update`), detect *before the real
build* which packages are not in the binary cache (would be built from
source), and take those packages from the nixpkgs revision that was in the
local `flake.lock` before the update (the "currently working" revision).

Decisions made with the user:
- Only relevant for the `update` path of `syncbuild` (not plain sync/build).
- "Currently working revision" = `nodes.nixpkgs.locked.rev` of the **local**
  `machines/leopard/flake.lock` before updating (not the server's active
  generation). `syncbuild` already wrote this into the `nixpkgs_pin` input
  (sed on `flake.nix`) before this change.
- Instead of `nix-forecast` / `nix-weather`, `nix build --dry-run` is used:
  it queries exactly the substituters leopard uses (cache.nixos.org, chaotic
  nyx cache, ...) and also counts paths already in leopard's local store.
  nix-forecast was later tested on leopard and rejected (see "nix-forecast
  evaluation" below).

## Context (repo layout relevant here)

- `machines/leopard/flake.nix` – flake of leopard. `nixpkgs.follows =
  "chaotic/nixpkgs"`. Has inputs `nixpkgs_pin` (rewritten by syncbuild) and
  `nixpkgs_pin_virtualbox`. `pkgs-pin` (= `import inputs.nixpkgs_pin`, only
  `allowUnfree`) is passed as specialArg and used manually in a few modules
  (`nixconfig/server/mealie.nix`, `stirlingpdf.nix`, ...). Config uses
  `cudaSupport = true`, chaotic + NUR overlays, CachyOS kernel.
- Flake eval needs `--impure` (reads
  `/home/robert/Nextcloud/code/mynixos/secrets/gitcrypt/params.json`, absolute
  path on leopard) and the repo must be git-crypt unlocked. This is why the
  analysis runs **on leopard**, not on the Mac.
- `dotfiles/sd/leopard/syncbuild` – runs on the Mac: optional update, rsync
  repo to leopard, optional remote build via `dotfiles/sd/leopard/rebuild`.
- Flakes only see git-tracked files → new files were `git add`ed (not committed).

## Changes made

### 1. `machines/leopard/pinned-packages.json` (new, staged)
Content `[]`. List of top-level attribute names to take from `nixpkgs_pin`.
Generated by `uncached-pins`; can be edited by hand.

### 2. `machines/leopard/pinned-packages.nix` (new, staged)
NixOS module, imported in `flake.nix` right after `./hardware.nix`:

```nix
{ config, lib, inputs, settings, ... }:
let
  pins = lib.importJSON ./pinned-packages.json;
  pkgsPinned = import inputs.nixpkgs_pin {
    inherit (settings) system;
    config = config.nixpkgs.config;   # same cudaSupport/allowUnfree/... as the system
  };
in
{
  nixpkgs.overlays = [ (_: _: lib.genAttrs pins (n: pkgsPinned.${n})) ];
}
```

Note: the pinned set gets the system's `nixpkgs.config` but *not* the system's
overlays (chaotic, NUR, ctranslate2 override). Fine for plain nixpkgs
packages; for overlay-modified packages the pinned version differs.

### 3. `machines/leopard/flake.nix` (modified)
Added `(./pinned-packages.nix)` to the `modules` list after `(./hardware.nix)`.

### 4. `dotfiles/sd/leopard/uncached-pins` (new, executable, staged)
Runs **on leopard**. Steps:
1. Writes `[]` to `pinned-packages.json` (pins from the previous update refer
   to an older `nixpkgs_pin`).
2. `nix build --dry-run --impure <toplevel>` and parses the
   "will be built:" block → list of `.drv` paths to build locally.
3. `nix eval --impure --expr` with `builtins.getFlake`: for each drv, derives
   the package name (`parseDrvName` of the store name) and keeps it only if
   `sys.pkgs.<name>.drvPath == drv` (i.e. it really is a top-level attr of the
   system's package set). For those it returns the drvPath of the same attr in
   `import nixpkgs_pin { config = sys.config.nixpkgs.config; }`.
4. For each candidate, `nix build --dry-run '<pinned drv>^*'`; if nothing
   would be built, it's pinned (prints `pin`), otherwise `skip`.
5. Writes the sorted list to `pinned-packages.json` and dry-runs the toplevel
   again, printing the new count of local builds.

### 5. `dotfiles/sd/leopard/syncbuild` (modified)
Inside `if update`, after `nix flake update`/`popd`:

```bash
rsync -rvhtz ~/Nextcloud/code/mynixos/ leopard:Nextcloud/code/mynixos/
ssh leopard bash Nextcloud/code/mynixos/dotfiles/sd/leopard/uncached-pins
rsync -vht leopard:Nextcloud/code/mynixos/machines/leopard/pinned-packages.json "$leopard/"
echo "Pinned to nixpkgs_pin: $(jq -r 'join(" ")' "$leopard/pinned-packages.json")"
```

The existing rsync + optional build after the `if` block is unchanged. Without
`update`, the existing pin list stays in effect.

## Known limitations / risks

- Only uncached drvs that are exactly a top-level package attr are pinnable.
  Kernel modules (`linuxPackages_cachyos.*`, `tuxedo-drivers`), overlay
  results (`ctranslate2` with CUDA), python/perl sub-packages, NixOS-generated
  files (etc, units, toplevel) are not matched and still build.
- Name heuristic: attr name = `parseDrvName` name. Packages whose attr name
  differs from their pname are missed (no false pins, since drvPath must match).
- Pinning a library overrides it for all dependents → can cause *more*
  rebuilds. The "With pins: N derivations" output shows this; remove names
  from the JSON if N increases.
- The Nix expression is built inside a bash double-quoted string (`\${n}`
  escapes) – fragile; first place to look if `nix eval` errors.
- `drvOf` uses `tryEval`; evaluation errors that `tryEval` can't catch
  (e.g. some `throw`-free aborts) would fail the whole step. `set -e` then
  aborts syncbuild before the build.
- Store-name parsing assumes `/nix/store/<32-char hash>-<name>.drv`
  (`substring 33 (len - 37)` on the basename).

## First real Run (2026-10-23): audacity failed, fixed

The build failed on `audacity-4.0.0` (QML AOT compile error) although the
working system had a cached audacity. Cause: `nixpkgs_pin` pointed at the
**new** nixpkgs (02c087f), not the working one (fe13242). syncbuild read the
rev from the local `flake.lock`, which an earlier `update` Run had already
bumped. So the pinned set was identical to the system's package set and
nothing could be pinned. Also, lines after `uncached-pins` used a misspelled
machine variable, so with `set -u` they would have aborted.

Fixes:
- syncbuild now reads the rev from the committed lock
  (`git show HEAD:machines/leopard/flake.lock`). Commit `flake.lock` only
  after a successful build, otherwise this has the same problem.
- Variable typo fixed.
- `uncached-pins` prints `same <attr>` when nixpkgs_pin yields the identical
  drv, so this misconfiguration is visible.
- `nixpkgs_pin` set to fe13242 by hand (+ `nix flake update nixpkgs_pin`).

Rerun result: 67 drvs to build → pins `audacity audiobookshelf calibre
paperless-ngx piper-tts` → 51. The remaining real builds are kernel-side
(linux 7.3 modules, initrd, tuxedo-drivers, new-lg4ff, kmodigest plus the
cargo/cargo-auditable/cargo-nextest toolchain it needs), which cannot be
pinned by top-level attr.

## nix-forecast evaluation (tested on leopard, 2026-10-23)

Same updated config, both tools installed on leopard:

| | `nix build --dry-Run --impure` | `nix-forecast 0.2.0 -s -c <flake>#nixosConfigurations.leopard -b <each substituter>` |
|---|---|---|
| Wall time | ~23 s | ~70 s |
| Result | 957 drvs "will be built" | 564 paths "uncached" (of 4720) |
| Overlap by name | 18 | 18 |

Rejected because:
- Slower: it asks every substituter about every closure path (4720 × 7),
  while the dry Run skips paths already in the local store.
- Wrong question: it reports "not in any cache", not "would be built". All
  564 paths it flagged were already in leopard's local store.
- Awkward to call: no `--impure` (needs `NIX_CONFIG="pure-eval = false"`),
  `-c` needs the full `#nixosConfigurations.leopard` path, and the only
  default cache is cache.nixos.org (each substituter must be passed with `-b`).

### Noise in the dry-Run "will be built" list
Of the 957 drvs, 818 have `allowSubstitutes = false` (505 in env as `""`,
313 via structuredAttrs as `false`). These are trivial builders
(`runCommandLocal`, `writeText`, unit files, fish completions, wrappers) that
Nix always builds locally, even if the output is in a cache. Example:
`deskreen-3.2.16` and `deskreen-3.2.16-bwrap` are listed as builds although
cache.nixos.org has both outputs. They are wrapper drvs with
`allowSubstitutes = false` (structuredAttrs). Only ~139 drvs are substitutable
builds, and many of those are config/firmware-zstd/completion drvs as well.

So the dry Run is correct (these really are built locally), but the raw
count overstates the cost. The attr-matching step in `uncached-pins` already
skips most of these. To get a meaningful count, filter out drvs with
`allowSubstitutes == false` via `nix derivation show` (check both `.env` and
`.structuredAttrs`).
